# TC StepUp 2026 — 스텝업 레포트 [ Step - Up Report ]

현대해상 스텝업 레포트(구 하이플래너 자가진단 레포트)를 웹앱으로 옮긴 것입니다.
기존에는 15MB 엑셀 파일에서 사번을 셀에 입력해 한 번에 한 명만 볼 수 있었고, 엑셀이 설치된 PC에서만 열렸습니다.
이 앱은 **어디서든(모바일 포함) 사번만 넣으면** 5개 탭을 보고, 그대로 **A4 5장으로 인쇄**하거나
**이미지 1장으로 카카오톡 공유**할 수 있게 합니다.

- 배포 주소 : https://comdoctor76-droid.github.io/TC_StepUp_2026/
- 관리자 화면 : https://comdoctor76-droid.github.io/TC_StepUp_2026/#/admin
- 문의 : 개인마케팅교육본부 / 영업교육운영파트

## 화면 구성

| 탭 | 원본 시트 | 내용 |
|---|---|---|
| 레포트 | `레포트` | 인적사항 · 현황Ⅰ(전체) · 현황Ⅱ(6개월) 전체 폭 비교표 (본인/TC 좌우 열 그룹) |
| C분석 | `C분석` | 고객 — 유지고객군, 월평균 신규고객, 연계고객, 6개월 추이, 소득군별 평균 (차트 5) |
| A분석 | `A분석` | 활동 — 인당건수, 보종별 월평균 건수, 신규/기존, 월별 추이 (차트 10) |
| M분석 | `M분석` | 시장 — 인보험 건수 구성비, 주력상품 보험료 구성비, 실손 세대별 (차트 8) |
| S분석 | `S분석` | 기술 — 인당/건당/최고 보험료, 상품별 평균, 암·심뇌 부보율 (차트 13) |
| 액션플랜 | `액션플랜` | 나의 강점/약점 × Action Plan 표(각 3행) + 서명란 (인쇄해서 손으로 적는 양식) |

모든 수치는 원본 워크북의 VLOOKUP / INDEX 수식을 1:1 이식했습니다.
각 계산 함수 위에 원본 셀 주소가 주석으로 남아 있습니다 (`src/calc/`).

### 조회기간 선택 (C/A/M/S 탭, 화면 전용)

> **⚠ 임의 기간 재계산은 불가능합니다 — 데이터가 없습니다.**
> Firestore 에 저장되는 것은 ① 엑셀이 **이미 집계해 둔 스칼라 88개**(`FIELDS`)와
> ② **정확히 6개월치 시계열 5종**(`retainLong/retainAuto/retainBoth/cntLong/custLong`,
> Q6·Q7 시트에서 6칸 고정 슬라이스)뿐입니다. 월별 원장·계약 단위 데이터는 저장되지
> 않으므로, 6개월을 벗어난 연·월 범위는 **어떤 계산으로도 만들어낼 수 없습니다.**

그래서 선택지별 실제 동작은 다음과 같습니다. 각 탭 상단이 이 범위를 직접 안내합니다.

| 탭 | 최근 6개월 ↔ 전체기간 | 기간선택(6개월 내 구간) |
|---|---|---|
| C분석 | — (원본이 전체기간 누계 하나뿐) | 유지고객 추이 그래프·표 |
| A분석 | 인당 가입건수 그래프 | 월별 추이 그래프 |
| M분석 | — (기간 구분 자체가 없음) | — |
| S분석 | 인당·건당·최고 금액 3개 그래프 | — |

A·S분석의 전체기간/6개월 전환이 가능한 이유는 **엑셀이 두 벌을 모두 계산해 두었기
때문**입니다(`longCustNet` 계열 ↔ `longCust6m` 계열). 새로 계산하는 것이 아닙니다.

임의 기간을 제대로 지원하려면 원본 엑셀에 **월 단위 시트**가 추가되어야 하고,
`src/data/schema.ts`·`parseWorkbook.ts`부터 다시 설계해야 합니다.

인쇄·이미지 출력물은 조회기간과 무관하게 **항상 원본과 같은 최근 6개월 기준**으로
고정됩니다 (각 탭의 `dense` 분기).

## 출력

### 전체 인쇄 (데스크톱)

상단 **「전체 인쇄」** → **인쇄 / PDF로 저장** 선택창.

- **인쇄** → 브라우저 인쇄 대화상자 → **A4 세로 6장**. 원본 엑셀의 `pageSetup`(A4 ·
  portrait · fitToPage=1, 시트당 1페이지)과 동일합니다. 대화상자에서 "PDF로 저장"을
  고르면 제안 파일명이 `성명(사번)_출력일시`로 뜹니다(인쇄 직전 `document.title`을
  잠깐 바꿨다가 복원 — `src/export/captureAll.ts`의 `printAll`).
- **PDF로 저장** → 인쇄 대화상자를 거치지 않고 앱이 직접 6페이지 PDF를 만들어
  (`src/export/pdf.ts`, `pdf-lib` 동적 import) 저장 위치를 묻습니다
  (`showSaveFilePicker` 지원 브라우저 — Chrome/Edge). 미지원 브라우저는 기본
  다운로드 폴더로 내려받습니다.

> **인쇄 글자 크기를 건드릴 때 주의**
> A4 한 장의 본문 높이는 954px 뿐이라 여유가 페이지당 14~61px 밖에 없습니다.
> `.dense` / `--dense` 계열 `font-size` 를 올리면 곧바로 페이지가 넘칩니다.
> 글자를 키웠으면 `src/tabs/*.tsx` 의 차트 높이(`const S = dense ? …`)를 함께 줄이고
> **반드시 `npm run verify` 로 6장이 넘치지 않는지 확인**하세요.

### 이미지 저장 · 카카오톡 공유 (모바일)

모바일에서 **「전체 인쇄」** 를 누르면 A4 6장을 세로로 이어붙인 **PNG 1장**(1191 × 10,154px)을 만들고
OS 공유 시트를 띄웁니다. 여기서 **카카오톡**을 고르면 그대로 전송됩니다.

- 파일명 : `성명(사번)_출력일시.png` — 예 `홍길동(1B9137)_20260727_1530.png`
- 공유 API 미지원 브라우저에서는 자동으로 다운로드됩니다.
- 해상도는 `pixelRatio 1.5` 고정입니다. 총 12.1M 픽셀로 iOS Safari 캔버스 한도(16.7M)를 넘지 않습니다.

## 매월 데이터 갱신 (운영 절차)

### 방법 1 — 관리자 화면 (권장)

1. `#/admin` 접속 → Firebase 관리자 계정으로 로그인
2. 원본 `.xlsx` 를 드래그 앤 드롭 (15MB 기준 20~30초 소요)
3. 검증 결과 확인 — 플래너 수, 벤치마크 구간, TC 표준그룹 유무, 6개월 추이 데이터
4. **기준월**(예 `202601-202606`), **레포트 캡션** 입력
   접속 비밀번호를 바꿀 때만 비밀번호 칸에 입력 (SHA-256 해시만 저장됩니다)
5. **Firestore 에 적재** — 진행률이 표시됩니다. 중단돼도 같은 파일로 다시 올리면 이어서 진행합니다.

### 방법 2 — CLI

```bash
npm run import -- ./원본.xlsx \
  --months 202601-202606 \
  --caption "(영업교육운영파트 / updated by 2026.6.30.)" \
  --viewer-password "접속비밀번호" \
  --key ./serviceAccount.json

# 적재 없이 검증만
npm run import -- ./원본.xlsx --dry-run
```

서비스 계정 키(`serviceAccount*.json`)와 원본 엑셀은 `.gitignore` 에 등록돼 있습니다. **절대 커밋하지 마세요.**

## 데이터 구조

원본 워크북에서 읽는 시트는 4개입니다.

| 시트 | 용도 |
|---|---|
| `input` | 원천 데이터. 16,249행 × 89열(B~CK), 플래너 1인 = 1행, 키 = B열 `사원번호` |
| `소득별Data` | 소득구간별 벤치마크. 33~47행이 `input` 과 같은 열 스키마 |
| `Q6 유지고객` | 최근 6개월 유지고객 추이 (장기 / 자동차 / 자장) |
| `Q7 장기건수` | 최근 6개월 장기 건수 · 고객수 추이 |

> ⚠️ `input` 헤더에는 중복 한글명이 있습니다 (`간편`·`퍼펙트`·`실손단독` 등이 보험료 블록 Z~AI 와
> 건수 블록 AJ~AS 에 각각 등장). 그래서 파서는 **헤더 문자열이 아니라 열 위치**로만 읽습니다.
> 원본의 열 순서가 바뀌면 `src/data/schema.ts` 를 함께 고쳐야 합니다.

### 계산 이식 시 반드시 지켜야 할 두 가지

시트마다 규칙이 다릅니다. 공용 함수로 묶으면 조용히 틀립니다.

**1. 소득군 밴드 목록이 C분석과 A분석에서 다릅니다**

```
C분석 (INCOME_BANDS) : 100↓ 100↑ 200↑ 300↑ [400↑] 500↑ 700↑ 1,000↑ 2,000↑ 3,000↑
A분석 (ACTION_BANDS) : 100↓ 100↑ 200↑ 300↑        500↑ 700↑ 1,000↑ [1,500↑] 2,000↑ 3,000↑
```
A분석에는 400↑ 이 없고 1,500↑ 이 있습니다. 재사용하면 표가 한 칸씩 밀립니다.

**2. M분석만 벤치마크에 `ROUND` 를 쓰지 않습니다**

신버전 워크북에서 `M분석!CX29:CZ29` 등 27개 셀의 `ROUND()` 가 삭제됐습니다.
C분석·A분석·S분석은 여전히 `ROUND` 를 씁니다. 그래서 `resolve.ts` 의 공용
`benchBlock()` 은 반올림을 유지하고, `market.ts` 안에서만 반올림을 뺍니다.
단, M분석에서도 **상품별 보험료(EG~EL)와 보험료 구성(DH~DK)은 `ROUND` 를 유지**합니다.

### Firestore

```
plannerShards/{000~255}   해시 샤딩. 샤드당 약 64명 · 137KB (문서 한도 1MB)
benchmarks/all            소득구간 15개 벤치마크 (문서 1개)
meta/incomeMap            소득구간 매핑 · 차상급 체인 · 백분위
meta/dataset              기준월 · 업로드 시각 · 행 수 · 캡션
meta/auth                 접속 비밀번호 SHA-256 해시
meta/uploadProgress       업로드 재개용
```

플래너 1명당 문서 1개로 저장하면 매월 16,249 writes 로 Spark 무료 한도(일 2만)에 근접합니다.
사번 앞 2자리로 나누면 `1d` 접두사에만 6,242행이 몰려 문서 1MB 한도를 넘습니다.
그래서 **FNV-1a 해시 기반 균등 샤딩**을 씁니다 — 매월 쓰기 **259건**, 리포트 1건당 읽기 **4건**.

`src/data/shard.ts` 의 해시 함수는 업로더와 조회 클라이언트가 공유합니다. **한쪽만 바꾸면 조회가 전부 실패합니다.**

> ⚠️ 샤드는 **문서 1건씩** 씁니다 (배치로 묶지 않습니다).
> 샤드 문서는 최대 166KB 인데, 20개를 `writeBatch` 로 묶으면 요청이 약 2.85MB 가 되고
> 브라우저 JS SDK 의 WebChannel 전송이 문서상 커밋 한도(10 MiB)보다 훨씬 낮은 실질 한계를 가져
> `Transaction too big. Decrease transaction size.` 로 실패합니다.
> 1건씩 쓰면 요청이 166KB 를 넘지 않아 어떤 전송 한계에도 걸리지 않습니다.
> 동시 4건 + 지수 백오프 재시도 3회로 처리하며, 256건이 대략 15~30초 걸립니다.

## 접근 권한

- **뷰어** : 공통 비밀번호 → SHA-256 대조 → Firebase 익명 인증 → Firestore 읽기 허용
- **관리자** : Firebase Auth 이메일 계정. `firestore.rules` 의 UID 화이트리스트에 등록해야 쓰기 가능

> ⚠️ 공통 비밀번호 방식이라 **비밀번호를 아는 사람은 임의의 사번을 조회할 수 있습니다.**
> 완전한 격리가 필요하면 사번별 계정 발급으로 전환해야 합니다.

### 최초 설정

1. Firebase 콘솔 > Authentication → **익명** 로그인 사용 설정
2. Firebase 콘솔 > Authentication → **이메일/비밀번호** 사용 설정 후 관리자 계정 1개 생성
3. 그 계정의 UID 를 `firestore.rules` 의 `isAdmin()` 목록에 넣고 규칙 배포
4. CLI 또는 관리자 화면에서 첫 데이터 적재 + 접속 비밀번호 설정

## 원본 워크북의 알려진 문제

이식하면서 발견한 원본 수식의 오류입니다.

| 위치 | 내용 | 이 앱의 처리 |
|---|---|---|
| `개요!BU25 = S분석!#REF!` | **S 점수 산식이 유실**됨 | 레이더에서 S축을 비우고 '산식 미확정' 표기. 산식을 주시면 반영합니다 |
| `레포트!L34`, `M34` | 머리글은 TC 표준그룹인데 차상급(M분석 30행)을 참조 | **원본 그대로 차상급 값**을 씁니다. 엑셀과 숫자를 100% 맞추기 위한 결정입니다 |
| `A분석!DQ31` | 인덱스 90(장기건수_M) 대신 85(장기건수_M5)를 재참조 | 올바른 값(장기건수_M)을 씁니다. 추이 그래프 마지막 점에만 쓰이며 표 수치와는 무관합니다 |
| `M분석!CY30` | 같은 행의 다른 셀은 이관제외인데 이 셀만 이관 포함 자동차고객수 | 원본 표시값과 맞추기 위해 **그대로** 두었습니다 |

## 버전

수정할 때마다 `src/version.ts` 의 `APP_VERSION` 을 **0.01 씩** 올리고 `CHANGELOG` 에 한 줄 남깁니다.
버전은 각 탭 상단 제목과 A4 페이지 하단에 표시됩니다.
